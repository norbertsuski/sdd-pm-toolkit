# pm-roadmap eval cases

Behavioral prompt fixtures for `pm-roadmap`. The fixture is `tests/fixtures/flat-root/context/` (project
`recipe-fridge`, PRD v1 with FR-001..FR-004 must-have and US-01..US-03). Copy it into a scratch git repo and delete
`foundation/recipe-fridge/roadmap.md` (and `archive/`, `changes/`) where a case says "no roadmap yet". To try one by
hand, run Claude Code with the plugin loaded (see the README, "Local testing"). Every case also implies the guardrails
in `SKILL.md`: every slice traces to a PRD id, no time units or estimates, no framework or file-path talk, never chain
into another skill.

| ID | Given | Invoke | Expected |
|---|---|---|---|
| RM-01 | The fixture PRD, no `roadmap.md`, `audience: plain` in `.sdd.local.yml`; baseline probes report everything absent (greenfield). | `/pm-roadmap` | PRD readiness scores 4/4 and proceeds. At most three anchor questions are asked (main goal, first piece worth building, biggest risk), each with a grounded Recommend as option 1, in plain language with no `S-NN`, "north star" or "Change ID". `foundation/recipe-fridge/roadmap.md` is written with frontmatter keys `project`, `version`, `status`, `created`, `updated`, `prd_version`, `main_goal`, `top_blocker` (no `audience`) and these `##` headings in order: `## Vision recap`, `## North star`, `## At a glance`, (`## Streams`), `## Baseline`, `## Foundations`, `## Slices`, `## Backlog Handoff`, `## Open Roadmap Questions`, `## Parked`, `## Done`. `## Done` is empty. |
| RM-02 | Same as RM-01. | (inspect the written file) | The `## Backlog Handoff` table header is exactly ``\| Roadmap ID \| Change ID \| Suggested issue title \| Ready for `/sdd-plan` \| Notes \|`` (column names unchanged, the literal header kept), has one row for every `F-NN` and `S-NN` and repeats each Change ID; no Notes cell names a command - a ready item says "Ready for a developer to plan". `## At a glance` has the six columns `ID`, `Change ID`, `Outcome (user can …)`, `Prerequisites`, `PRD refs`, `Status`, with statuses only `proposed`, `ready` or `blocked` (never `done`, `planning`, `in-progress`). |
| RM-03 | PRD whose must-have FR-004 is not mapped to any slice in the draft (simulate by asking for a roadmap that omits shopping lists). | `/pm-roadmap` | Step 8 self-review check 4 fails ("FR-004 (must-have) is not covered by any slice"), the write is aborted with the specific failure, and no `roadmap.md` is created. Cancel writes nothing. |

The roadmap file is byte-identical to a technical-mode run. Nothing is printed or copied that names a developer-only command. |
