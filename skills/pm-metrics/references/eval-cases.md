# pm-metrics eval cases

Behavioral prompt fixtures for `pm-metrics`. The fixture project is `tests/fixtures/flat-root/context/` (project
`recipe-fridge`: greenfield `prd.md`, `status: draft`, `version: 1`; Success Criteria with two Primary, one Secondary and two
Guardrails bullets; three user stories US-01..US-03; five FRs). The shared fixture is **not changed** for these cases: where a case needs
a PRD that differs from it, the Given describes the variant to apply to a scratch copy. To try one by hand, copy the fixture into a scratch
git repo and run Claude Code with the plugin loaded (see the README, "Local testing"). Every case also implies the guardrails in
`SKILL.md` (never invents a number, every criterion mapped, the person picks the north-star metric, no silent overwrite, never edits the PRD).

About the fixture as it stands: five Success Criteria bullets, so the mapping has five rows. The PRD states numbers for Primary 1 (60%)
and Primary 2 (40%), a window for Primary 1 (one minute), Primary 2 (end of launch month) and Secondary 1 (two weeks), and a
threshold for Guardrail 1 (three seconds); it states no baseline for any criterion, no share for Secondary 1, and no owner. No story records
that a user *cooked* a recipe, which Primary 2 counts.

| ID | Given | Invoke | Expected |
|---|---|---|---|
| MT-01 | The fixture as it stands; no `metrics.md`; the person picks the recommended north-star metric and answers "skip all remaining" when asked for baselines and owners. | `/pm-metrics recipe-fridge` | Contract check passes (10 greenfield headings and the three Success Criteria subsections). 2 to 3 north-star candidates are shown, recommended first, each with a verbatim Primary quote and no number the PRD lacks. After the pick, a short input-metric tree (3 to 5 inputs, each with a PRD ref). The written `metrics.md` has the frontmatter `project`, `prd_version: 1`, `created`, `updated` and the six headings in order. **All five Success Criteria bullets occur verbatim, one row each, in `## Success Criteria Mapping`** (two `[Primary]`, one `[Secondary]`, two `[Guardrail]`), under the header `\| PRD criterion \| Metric \| Target \| Baseline \| Window \| Owner \|`. Targets 60%, 40% and three seconds come from the bullets; every Baseline is `TBD — Owner: <role>`; the Secondary target is `TBD — Owner: product manager`. `## Guardrail Metrics` has exactly two rows. Fail if a bullet is missing or reworded, a number appears that is not in the PRD or the person's answers, or the file differs from the layout in `metrics-format.md`. |
| MT-02 | The fixture; at the Secondary criterion the person answers "I don't know" for the target and for the baseline, and gives no owner. | `/pm-metrics recipe-fridge` | The skill takes no estimate and offers no benchmark. The Secondary row's Target, Baseline and Owner cells are `TBD — Owner: <role>` (role named, product manager or analytics), the row is still written, and `## Open Questions` has an entry for each blank (one entry may list several blanks of the row, with an `Affects:` ref to the criterion). The other rows keep the values the PRD gave. The self-check reports no empty cell. Fail if any cell is empty, filled with a made-up number or typical rate, or has `TBD` without a matching Open Question. |
| MT-03 | The fixture; the tracking plan is derived after the mapping. | `/pm-metrics recipe-fridge` | `## Tracking Plan` uses the header `\| Event \| Trigger \| Properties \| PRD ref \|`. Every event name is `object_action` past-tense snake_case (for example `fridge_item_added`, `recipe_suggestion_opened`, `recipe_saved`, `shopping_list_item_checked`); none is verb-first (`save_recipe`), present tense (`recipe_save`), camelCase or hyphenated. **Every event cites at least one existing `US-NN`** in its PRD ref, and each of US-01, US-02 and US-03 has at least one event. No event is invented for "cooked a suggested recipe": `## Open Questions` says Primary 2 and the north-star metric count it and no story records it, and points at `/pm-prd-review`. Properties are ids or counts, never names or free text. Fail if a name breaks the pattern, an event has no `US-NN`, a story has no event, or an event is invented for a missing story. |
| MT-04 | A `metrics.md` already exists for the project, written earlier, in which the person had supplied the baseline for Primary 1 (`22% (PM)`) and a Secondary target; the fixture PRD has since gained a third Guardrails bullet. | `/pm-metrics recipe-fridge`, then at the question choose Merge | Before writing anything, the skill shows a **diff** between the existing file and the new draft (hunks under their `##` headings) and asks "Merge (Recommended) / Overwrite (keeps its created date) / Cancel / Not sure". On Merge it shows the merged result as a second diff and asks before writing. After writing: the baseline `22% (PM)` and the Secondary target are still there (a given value is never replaced by `TBD` or a derived one), the new guardrail has its mapping row and guardrail row, `created` is unchanged and `updated` is today, `prd_version` reflects the current PRD. No row is deleted silently. Choosing Overwrite instead writes the new draft, keeps `created`, and carries over no value; choosing Cancel (or no answer) writes nothing. Fail if the file is written before the question, a given value is lost on Merge, or `created` changes. |
| MT-05 | Scratch copy of the fixture with `### Guardrails` and its bullets removed from `## Success Criteria` (all ten `##` headings still present). Variant: also the case with `## Success Criteria` itself deleted. | `/pm-metrics recipe-fridge` | The contract check finds the missing subsection (the first variant) and prints `CONTRACT MISMATCH: prd.md missing ### Guardrails` (second variant: `prd.md missing ## Success Criteria`, plus the subsections when they were deleted with it). The skill STOPs: no north-star candidates, no questions, no `metrics.md`, no attempt to add the subsection. Plain mode also says in a sentence that the product write-up lacks a clearly labelled must-not-break section and the PRD step should be re-run. Fail if any metrics content appears, a file is written, or the skill adds the missing section itself. |
| MT-06 | Scratch copy of the fixture converted to a brownfield PRD (`context_type: brownfield`, the 11 brownfield headings, `## Scope of Change` with bullets `[new] …`, `[modified] …`, `[removed] …`, `[preserved] …` instead of the FR lines; same Success Criteria and stories). | `/pm-metrics recipe-fridge` | The contract check uses the brownfield heading list. Requirements are read from `## Scope of Change`; cited as `Scope [new] "<first words>"` since they have no ids. A `[removed]` item yields no event; a `[preserved]` item is context for guardrails and may appear as an Open Question when no guardrail covers it. Everything else as MT-01 and MT-03: all Success Criteria bullets mapped, events cite `US-NN`. Fail if the skill looks for `FR-NNN` lines and reports none, or fabricates FR ids. |
| MT-07 | The fixture with the numbers removed from the two Primary bullets ("Most weekly active users open a recipe suggestion quickly.", "Many weekly active users cook a suggested recipe regularly."). | `/pm-metrics recipe-fridge`, the person picks the recommended candidate | Candidates are still proposed, each quoting the vague Primary line, with no number. The Primary rows' Targets and Windows are asked for; if skipped they are `TBD — Owner: product manager` with Open Questions, and the skill suggests `/pm-prd-review` for the vague criteria without editing `prd.md`. The skill never offers "typical" targets. Fail if a percentage or time appears in a Primary row that the person did not give, or `prd.md` is touched. |
