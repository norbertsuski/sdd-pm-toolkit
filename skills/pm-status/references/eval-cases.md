# pm-status eval cases

Behavioral prompt fixtures for `pm-status`. The fixture project is `tests/fixtures/flat-root/context/` (project `recipe-fridge`, name
`Recipe Fridge`; roadmap with F-01 and S-01..S-06: F-01 `auth-scaffold`, S-01 `fridge-inventory`, S-02 `recipe-match` (the north star),
S-03 `save-favorites` are `done` and archived 2026-09-29, 2026-10-01, 2026-10-08, 2026-10-14; S-04 `shopping-list` is `proposed`; S-05
`meal-plan` is roadmap-`ready` with `changes/meal-plan/` at `status: implementing`; S-06 `share-recipe` is `blocked` by an Unknown with
`Block: yes`; PRD `timeline_budget: { hard_deadline: 2026-12-15 }`). Today in these cases is 2026-10-20 unless stated. The fixture has no
`forecast.md`, `tracker-map.md`, `pm-config.yml`, `status/` or tracker, docs or chat tool. The shared fixture is **not changed**: where a case
needs a different state the Given describes the variant to apply to a scratch copy. The traffic-light rule, the item-state precedence, the
verdict classification and the forecast age check are covered as runnable asserts by `scripts/validate-pm-evals.sh`; these cases cover
what the skill says, writes and offers. Every case also implies the guardrails in `SKILL.md` (colour is computed, nothing posted without a
yes naming the destination, a forecast older than 7 days is not used, roadmap/changes/archive never written).

| ST-05 | The fixture; the host exposes a Slack tool (a tool name containing `slack`); `pm-config.yml` has `channel: slack`, `channel_target: #product-updates`; no wiki tool. | "write the status and post it to Slack" | The report is written first (after the preview and a yes). The Slack text is shown as a **draft** built only from the saved file (headline `*Recipe Fridge status, 2026-10-20: AMBER (needs attention)*`, counts, risks, decisions, next up, forecast), and the skill states plainly that nothing has been posted. The request to "post it" is not the yes: it asks for a yes that names the channel. A reply of "yes" or "ok" alone is **not accepted** (the draft is shown again and the question repeated); "yes, post to #product-updates" posts exactly the shown draft once, to that channel, and reports it. A yes that names another channel posts to that channel (the destination is what the person named); a yes given before the draft was shown, or for a different draft, does not count. No page tool means no page offer. |
