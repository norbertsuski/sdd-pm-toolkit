# pm-shape eval cases

Behavioral prompt fixtures for `pm-shape`. The fixture is `tests/fixtures/flat-root/context/` (project
`recipe-fridge`; it has no `.sdd.local.yml`, so audience resolution starts from "absent"). To try one by hand, copy
it into a scratch git repo and run Claude Code with the plugin loaded (see the README, "Local testing"). Every case
also implies the guardrails in `SKILL.md`: facilitator not generator (no invented content), no stack questions,
`audience` never written into `shape-notes.md`, never chain into `/pm-prd`.

| ID | Given | Invoke | Expected |
|---|---|---|---|
| SH-01 | A repo with no `.sdd.yml` anywhere. | `/pm-shape a recipe app that suggests meals from the fridge` | Step 0 finds no root and asks "Run /pm-init now?" with Yes (Recommended) and No. On Yes it invokes `/pm-init` by tool call (not Bash), re-runs discovery and continues to audience resolution; on No it prints "Stopping. Run `/pm-init` when ready, then re-invoke `/pm-shape`." and writes nothing. Fail if the skill scaffolds `context/` itself. |
| SH-02 | `foundation/meal-planner/shape-notes.md` exists with `checkpoint: { current_phase: 3, phases_completed: [1, 2], frs_drafted: 0, quality_check_status: pending }` and `context_type: greenfield`. | `/pm-shape` | Step 0.5 finds the file, prints the "Found a prior shape session" summary (current phase 3, phases 1 and 2 completed) and offers Resume from Phase 3 (Recommended) / Restart / Cancel. On Resume, phases 1 and 2 are summarized in one or two sentences each and not replayed, the project-folder step (0.6) is skipped, auto-detection is skipped because `context_type` is already set, and the next questions are Phase 3's. On Restart the old file moves to `foundation/archive/shape-notes-meal-planner-<YYYY-MM-DD-HHMM>.md`. |
| SH-03 | The fixture root, no `.sdd.local.yml`; the user is a product owner. | `/pm-shape a meal planner for families` | The audience question is asked once; "product owner" maps to `plain`; `.gitignore` containing `.sdd.local.yml` is created before `.sdd.local.yml` (`audience: plain`). Unanswered also means `plain`. From then on no operator-facing text names FR/NFR numbering, "greenfield", "brownfield", "Socratic", file paths or schema sections, and options are plain choices. The `shape-notes.md` frontmatter never contains `audience`. |
| SH-04 | Phases 1 to 7 finished in plain mode for the project "Meal Planner"; one technical choice was made silently (context type auto-detected). | (end of the run) | `shape-notes.md` is schema-identical to a technical-mode run (10 greenfield body sections, `checkpoint:` block with `current_phase: 8`, `delivery_mode: product-feature`, `timeline_budget` null or `{ hard_deadline }`) plus an `## Auto-decisions (for review)` block listing the decision. The operator sees the plain handoff (2-4 sentences, one sentence on what's next naming the step in words with `/pm-prd` once in parentheses, "Want me to keep going?"), not the `SHAPE COMPLETE` block or the clipboard command; `/pm-prd` is still copied to the clipboard silently. The skill stops; it does not run `/pm-prd`. |
| SH-05 | Phase 6 (product framing); the user volunteers "we should use Postgres and avoid PHP". | (answer during Phase 6) | The skill does not ask about or endorse a stack. The remark is captured in the body of `shape-notes.md` under `## Forward: tech-stack` (informational, for the developer who picks the stack) and is NOT added to `## Non-Goals`; a scope-style avoid ("avoid: building our own recommendation algorithm") does go to `## Non-Goals` with a one-line rationale. |
| SH-06 | `foundation/recipe-fridge/shape-notes.md` already exists and the user names the same project again as a new idea. | `/pm-shape a recipe app` then confirms the name "Recipe Fridge" | Step 0.6 derives the slug `recipe-fridge`, finds the file and does not overwrite it: it returns to the Step 0.5 resume offer for that file. Fail if the existing file is replaced or truncated. |
