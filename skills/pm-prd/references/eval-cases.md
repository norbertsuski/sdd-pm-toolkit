# pm-prd eval cases

Behavioral prompt fixtures for `pm-prd`. The fixture is `tests/fixtures/flat-root/context/` (project
`recipe-fridge`; no `.sdd.local.yml`). Shape-notes inputs are small files you place under a scratch copy of the
fixture (a `checkpoint:` block plus the sections a finished shape run leaves). To try one by hand, run Claude Code
with the plugin loaded (see the README, "Local testing"). Every case also implies the guardrails in `SKILL.md`:
generator not author (gaps go to `## Open Questions` verbatim), no stack vocabulary, never chain.

| ID | Given | Invoke | Expected |
|---|---|---|---|
| PD-01 | `foundation/recipe-fridge/shape-notes.md` from a finished greenfield run: `checkpoint.current_phase: 8`, `context_type: greenfield`, a one-sentence business rule, FR-001..FR-006 with Given/When/Then stories, no `prd.md` yet. | `/pm-prd` | The input assessment scores 4/4 and proceeds silently. `foundation/recipe-fridge/prd.md` is written beside the notes with exactly these ten headings in order: `## Vision & Problem Statement`, `## User & Persona`, `## Success Criteria`, `## User Stories`, `## Functional Requirements`, `## Non-Functional Requirements`, `## Business Logic`, `## Access Control`, `## Non-Goals`, `## Open Questions`; frontmatter has `project`, `version: 1`, `status: draft`, `created`, `context_type`, `product_type`, `target_scale`, `timeline_budget` and no `audience`. `## Success Criteria` has `### Primary`, `### Secondary`, `### Guardrails`. |
| PD-02 | A brownfield `shape-notes.md` (`context_type: brownfield`, a `## Current System` section, `## Constraints & Preserved Behavior`). | `/pm-prd` | The 11-section brownfield template is used: `## Current System Overview`, `## Problem Statement & Motivation`, `## User & Persona`, `## Success Criteria`, `## User Stories`, `## Scope of Change`, `## Constraints & Compatibility`, `## Business Logic Changes`, `## Access Control Changes`, `## Non-Goals`, `## Open Questions`. Only `## Current System Overview` may name the existing stack. |
| PD-03 | A pasted raw-notes file with no `checkpoint:` block, no FR-NNN lines and no Given/When/Then; `audience` absent in `.sdd.local.yml` (the question was answered "product owner" earlier, so `plain`). | `/pm-prd @raw-notes.md` | Score is below 2, so the thin-input warning appears, but in plain words: no "N/4", no signal names, no "shape heuristic" ("your notes are a bit thin ... want me to go ahead, or answer a few more questions first?"), mapped to the three branches (run `/pm-shape` first, proceed anyway, cancel). On "proceed anyway" every missing field becomes `# TODO: <field> - see Open Questions` with a matching numbered Open Question. |
| PD-04 | `prd.md` already exists in the project folder. | `/pm-prd` | After validation the skill asks Save as `prd-v2.md` (Recommended) / Overwrite / Abort. The first writes `prd-v2.md` with `version: 2` and leaves `prd.md` unchanged; Overwrite keeps `version: 1`; Abort writes nothing. |
| PD-05 | Shape notes whose Phase 6 left a `## Forward: tech-stack` block ("Postgres, avoid PHP") and a FR that says "stored in Stripe". | `/pm-prd` | `team_profile`, `tech_preferences`, `deployment_constraint` are not emitted into the frontmatter. The content lint flags the vendor name in the FR body, the skill does not silently translate it, and the hand-off lists the forward item under "forward to the developer's next step". The next step it names for the PM is `/pm-prd-review`; a developer's stack selection is mentioned generically, with no command. |
| PD-06 | Same as PD-01, `audience` resolved to `plain`. | (end of run) | The operator does not see the `PRD GENERATED` block or the clipboard command; the plain handoff says what the write-up now contains, how many things still need deciding (Open Questions counted, section not named) and what comes next ("I can review it for gaps", `/pm-prd-review` once in parentheses), then "Want me to keep going?". `/pm-prd-review` is copied to the clipboard silently. The `prd.md` is byte-identical to a technical-mode run. |
